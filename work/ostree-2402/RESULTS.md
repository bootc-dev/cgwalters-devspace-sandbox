## Design

When finalize runs, it opens a detached clone of the boot filesystem itself.
It does not get an fd handed over from the hold process. When `/boot` lives on
the physical root (`/sysroot/boot/loader` is a symlink), the clone and every
read come from `/sysroot/boot`. That path is never automounted, so an expired
`boot.automount` in front of the generator's `/boot` bind mount can't take it
away. Otherwise they come from `/boot`.

The clone is made with `open_tree(OPEN_TREE_CLONE)` and
`mount_setattr(attr_clr=RDONLY)`, then reopened as a directory fd so that
`syncfs` and `FIFREEZE` work on it. If the kernel lacks the new mount API
(ENOSYS/EPERM), or the filesystem itself is read-only, it falls back to the
remount path ostree uses today.

The `/boot` remount is still attempted, because path-based bootloader
backends (grub2-mkconfig, syslinux, uboot, zipl, aboot) write through
`/boot`. A failed remount is fatal only when there is no other writable boot
fd. All core `sysroot_fd + "boot/..."` accesses now go through `boot_fd`.

The fd handover options were rejected for these reasons. The systemd fd
store only returns fds to the same unit. Making the holder the finalizer
changes shutdown ordering. pidfd_getfd or SCM_RIGHTS would add IPC and
SELinux surface.

`finalize-staged --hold` now opens `/boot` explicitly. Without that, the
first build deadlocked in the VM. The hold stopped pinning `/boot`, the
automount expired, and stopping `boot.mount` stopped
`ostree-finalize-staged.service` (RequiresMountsFor=/boot). Finalize then
blocked in `statfs` → `autofs_expire_wait`. Stack traces were captured.

The VM pass in step 2 does not prove that the clone was used. With `/boot` on
the physical root, remounting `/sysroot` already makes `/sysroot/boot`
writable. Whether the clone was taken is logged only at debug level.

Path-based bootloader backends (grub2, syslinux, uboot, zipl, aboot) still
write through `/boot`. In the reported scenario `boot.mount` is already gone
when finalize runs, so the fix covers BLS-only setups (`bootloader=none`).

The boot filesystem is now chosen only by whether `/sysroot/boot/loader` is a
symlink. Unlike the generator, this ignores an fstab entry for `/boot`, so a
stale symlink on the root filesystem would hide a separate `/boot`.

The new test puts a writable tmpfs over `/boot`, so it would pass without the
clone commit and never exercises finalize. Its karg is also never removed.

Scripts used are in `scripts/`. They expect the key at `/var/tmp/w/ssh/id`
and a CentOS Stream 10 `virtiofsd` passed in `VIRTIOFSD_BIN`.
