## Prototype

`patches/` is `git format-patch` output against ostreedev/ostree main a4cb6781. Patches 0001-0004 are PR 3690 as it stands. Patches 0005-0006 are the spike:

- 0005 adds `src/libostree/ostree-bootfs.c`. On a booted system with a separate `/boot`, it opens the boot filesystem as a detached mount and never touches the `/boot` path. It first tries `open_tree(OPEN_TREE_CLONE)` of the `/boot` mount, opened `O_PATH` so an automount is not triggered. If that mount isn't there, it uses `fsopen`/`fsconfig`/`fsmount` on the fstab device or `/dev/disk/by-designator/xbootldr`. It falls back to the path when the process is unprivileged or the new mount API is missing. To make it writable, it uses `fspick` plus a reconfigure to `rw`, not a remount of `/boot`. When `/boot` is on root, PR 3690 already opens `/sysroot/boot`.
- 0006 changes the finalize units from `RequiresMountsFor=/boot` to `WantsMountsFor=/boot`. An expiring automount then no longer stops the unit, which would finalize early. This makes the `/boot` hold from PR 3690 unnecessary.

The branch was not pushed to cgwalters-forge/ostree. Nothing went upstream.

## Test evidence so far

Tests ran on Fedora 44 VMs: KVM nested in a Fedora Cloud builder, SeaBIOS boot so the ESP is unused, fedora-bootc:44 images with ostree overlaid. The harness is in `harness/`. Only the pilot runs below completed. The PR 3690 and Silverblue runs were queued but never finished.

| variant | layout | result |
|---|---|---|
| stock ostree 2026.4 | /boot on root, gpt-auto automount expired | staged deployment LOST: `Remounting /boot read-write: Invalid argument` (the bug reproduces) |
| ostree main a4cb6781 | same | LOST, same error |
| dirfd (0001-0006) | same | staged deployment booted; BLS entries labelled `boot_t` |
| dirfd, first revision | separate ext4 /boot (bootc writes `auto ro` to fstab) | LOST: `ioctl(FIFREEZE): Bad file descriptor` |

The last failure happened because mount fds from `open_tree`/`fsmount` are `O_PATH`. That revision is fixed in 0005: it returns an `openat(mnt, ".")` directory fd. **The fix is not yet tested in a VM.** On stock 2026.4, `bootc status` succeeded even after the automount expired.
