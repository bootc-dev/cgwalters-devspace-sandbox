## What ran

The VMs are the same as in devspace PR 30: SeaBIOS q35, so the ESP is unused
and gpt-auto stacks `boot.automount` on /boot, with SELinux enforcing. The
images are `quay.io/fedora/fedora-bootc:44` with ostree built from source
(`scripts/Containerfile`). This host had no qemu, virtiofsd or root, so bcvk
0.22.0 and qemu ran inside a privileged container
(`scripts/Containerfile.vmhost`). `scripts/idle-stage-reboot.sh` is unchanged
from PR 30; `vm.sh` only takes a `QEMU` override. All logs are in `logs/`.

- **main a4cb6781, /boot on the root partition: bug reproduces**
  (`main-run.out`). After the automount expired, `unshare -m ostree admin status`
  failed with `fstatat(boot/loader): Operation not permitted`. At shutdown:
  `error: Remounting /boot read-write: Invalid argument`. The staged `.1` was
  dropped and `.0` booted again.
- **Fix, /boot on the root partition: pass** (`fixed-run.out`). After staging
  and 190 s idle, the bind mount was still under the autofs mount, so `--hold`
  kept it from expiring. `unshare -m` status returned 0. Finalize ran only at

  booted with `bz2402=rework`.
- **Fix, separate ext4 /boot** (`sepboot-run.out`, disk from
  `scripts/install-separate-boot.sh`): pass. /boot is mounted `ro` from fstab,

- **Fix, soft-reboot** (`soft-reboot.out`): pass. I staged a redeploy, ran
  `prepare-soft-reboot`, and idled 190 s; the bind mount was still held. Then

  up with uptime carried over. The
  `boot.automount: Path /boot is already a mount point` line after it is
  pre-existing soft-reboot behaviour that PR 30 already noted.

## Not verified

- With /boot on the physical root, the path-based bootloader backends
  (grub2-mkconfig, syslinux, uboot, zipl, aboot) would now see a read-only
  /boot, because nothing remounts it. Per the review, those systems use a
  separate /boot. No such system was tested.
- The `--hold` branch that leaves a real ESP at /boot unheld wasn't exercised:
  in these VMs, /boot is always ostree's bind mount.
- Only Fedora 44 (kernel 7.2, systemd 259) was tested, not CentOS Stream 10.
- The bootc tmt test ran once per image, with /boot on the root partition
  only.
